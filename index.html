Parte 1: Leitura de Código (Bend2)

Os trechos abaixo estão escritos em Bend2, uma linguagem funcional. A sintaxe relevante:

  • type Nome { Ctor1{...} Ctor2{...} } — tipo algébrico (ADT)
  • def f(x: T) -> R: body — definição de função
  • match x: case Ctor{a, b}: ... — pattern matching
  • x => body — lambda
  • A -> B — tipo função

IMPORTANTE: NÃO use IA nesta parte. Queremos suas próprias palavras e seu conhecimento atual. Respostas geradas por IA serão desconsideradas.

Questão 1 — O que esse código faz?
type Tree {
  leaf{}
  node{U32, Tree, Tree}
}

def foo(t: Tree) -> Tree:
  match t:
    case leaf{}:
      leaf{}
    case node{v, l, r}:
      node{v, foo(r), foo(l)}

Parte 2: Code Review

Contexto: O VibiMon é um RPG online retro feito em TypeScript, organizado no estilo funcional puro (como Haskell).

  • Todos os tipos do jogo são definidos em src/game/Type.ts como tipos algébricos.
  • Para cada tipo, existe um arquivo src/game/Type/NomeDoTipo.ts com funções puras relacionadas (ex: get_player_hp : Player -> number fica em Type/Player.ts).
  • Todas as funções são puras e imutáveis.
  • O estado do jogo (State) funciona como um banco de dados em memória: todo objeto tem um caminho único na árvore de State (ex: NPCs ficam em player.map[pos].entity). Essa é a fonte autoritária de verdade — nenhum dado é duplicado.
  • O jogo usa uma arquitetura de event stream: há um estado inicial, e eventos/transações dos jogadores alteram esse estado. O módulo de rede (VibiNet) cuida da conectividade de forma transparente.

Neste PR, uma IA tentou refatorar o jogo para introduzir suporte a multiplayer. Antes, o State só suportava 1 jogador. O tech lead rejeitou o PR.
