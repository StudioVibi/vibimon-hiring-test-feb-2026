Parte 1: Leitura de Codigo (Bend2)

Os trechos abaixo estao escritos em Bend2, uma linguagem funcional com tipos algebricos, pattern matching e lambdas. A sintaxe relevante:

  • type Nome { Ctor1{...} Ctor2{...} } — define um tipo algebrico (ADT) com construtores
  • def f(x: T) -> R: body — define uma funcao
  • match x: case Ctor{a, b}: ... — pattern matching sobre construtores
  • x => body — funcao anonima (lambda)
  • A -> B — tipo funcao de A para B

Para cada trecho, explique com suas proprias palavras o que o codigo faz, quais padroes/tecnicas estao sendo usados e como ele opera.

Questao 1
type Tree {
  leaf{}
  node{U32, Tree, Tree}
}

def foo(t: Tree) -> Tree:
  match t:
    case leaf{}:
      leaf{}
    case node{v, l, r}:
      node{v, foo(r), foo(l)}

Parte 2: Code Review

Contexto: O VibiMon e um RPG online retro feito em TypeScript, organizado no estilo funcional puro (como Haskell).

  • Todos os tipos do jogo sao definidos em src/game/Type.ts como tipos algebricos.
  • Para cada tipo, existe um arquivo em src/game/Type/NomeDoTipo.ts com funcoes puras relacionadas (ex: get_player_hp : Player -> number fica em Type/Player.ts).
  • Todas as funcoes sao puras e imutaveis.
  • O estado do jogo (State) funciona como um banco de dados em memoria: todo objeto do jogo tem um caminho unico dentro da arvore de State (ex: NPCs ficam em player.map[pos].entity). Essa e a fonte autoritaria de verdade — nenhum dado e duplicado em outro lugar.
  • O jogo usa uma arquitetura de event stream: ha um estado inicial, e eventos/transacoes dos jogadores alteram esse estado. O modulo de rede (VibiNet) cuida da conectividade de forma transparente — nao implementamos networking, apenas arquitetamos o jogo para funcionar assim.

Neste PR, uma IA tentou refatorar o jogo para introduzir suporte a multiplayer. Antes, o State so suportava 1 jogador. O tech lead rejeitou o PR.
